# Задачи упрощения Telegram-интерфейса

## Задача 1. Сократить главное меню

**Описание:** Убрать семь лишних кнопок, переименовать возврат упражнения и добавить заметную отмену.

**Критерии приёмки:**
- [x] В меню нет кнопок `Завтра`, `Восстановление`, `Расписание`, `Напоминания`, `Прогрессия`, `Данные`, `Помощь`.
- [x] `🔄 Возврат` заменён на `🧪 Возврат упражнения`.
- [x] `❌ Отмена` вызывает `/cancel` из любой строки меню.

**Проверка:**
- [x] Тесты меню проходят.
- [ ] Ручная проверка `/menu` в Telegram.

**Зависимости:** Нет.

**Предполагаемые файлы:** `src/menu.ts`, `tests/menu.test.ts`, `src/index.ts`.

**Размер:** Средний.

## Задача 2. Удалять временные сообщения при отмене

**Описание:** Добавить реестр сообщений активных диалогов и безопасную пакетную очистку через Telegram Bot API.

**Критерии приёмки:**
- [ ] Временные входящие и исходящие сообщения имеют ID и тип сценария.
- [ ] `❌ Отмена` закрывает активный сценарий и удаляет связанные сообщения моложе 48 часов.
- [ ] Ошибка удаления не отменяет сохранение или отмену данных.

**Проверка:**
- [ ] Тест Telegram API проверяет `deleteMessages` без раскрытия токена.
- [ ] Интеграционный тест отмены замеров проходит.
- [ ] Ручная проверка ошибочного нажатия `Замеры -> Отмена`.

**Зависимости:** Задача 1.

**Предполагаемые файлы:** новая миграция, `src/telegram.ts`, новый модуль временных сообщений, `src/index.ts`, тесты.

**Размер:** Средний.

## Контрольная точка 1

- [ ] Главное меню сокращено.
- [ ] Отмена работает из меню.
- [ ] Удаление сообщений не затрагивает итоговые записи.

## Задача 3. Добавить подменю и историю замеров

**Описание:** Разделить кнопку замеров на ввод нового комплекта и просмотр истории.

**Критерии приёмки:**
- [ ] `📏 Замеры` показывает `Сделать замеры`, `История замеров`, `Отмена`.
- [ ] История показывает последние даты, семь значений и изменения к предыдущей дате.
- [ ] Просмотр истории не вызывает Gemini и не изменяет БД.

**Проверка:**
- [ ] Тест форматирования истории.
- [ ] Интеграционный тест чтения нескольких дат.
- [ ] Ручная проверка обеих веток Telegram.

**Зависимости:** Задача 2.

**Предполагаемые файлы:** `src/body-tracking.ts`, `src/body-tracking-db.ts`, `src/index.ts`, тесты.

**Размер:** Средний.

## Задача 4. Очищать завершённый диалог замеров

**Описание:** После седьмого ответа удалять промежуточные вопросы и числовые ответы, оставляя одну итоговую сводку.

**Критерии приёмки:**
- [ ] Семь значений сначала надёжно сохранены, затем запускается очистка.
- [ ] В чате остаётся один итог с датой и семью значениями.
- [ ] Сбой Telegram-очистки не удаляет замеры из БД.

**Проверка:**
- [ ] Интеграционный тест порядка `save -> cleanup`.
- [ ] Ручная проверка полного ввода в Telegram.

**Зависимости:** Задачи 2-3.

**Предполагаемые файлы:** модуль временных сообщений, `src/body-tracking-db.ts`, `src/index.ts`, тесты.

**Размер:** Средний.

## Задача 5. Запретить тренировку на завтра

**Описание:** Удалить будущую генерацию и сделать текущий чекин обязательным условием любого нового плана.

**Критерии приёмки:**
- [ ] `/tomorrow` не вызывает Gemini и объясняет, что план создаётся только в день тренировки.
- [ ] `/today` требует актуальный чекин до нового или ранее сохранённого плана.
- [ ] Нельзя обойти болезнь, красные флаги или недостаток данных старым планом.

**Проверка:**
- [ ] Тест отсутствия вызова Gemini для `/tomorrow`.
- [ ] Тест обязательного чекина для кэшированного плана.
- [ ] Ручная проверка в Telegram.

**Зависимости:** Задача 1.

**Предполагаемые файлы:** `src/index.ts`, расписание, тесты генерации.

**Размер:** Средний.

## Контрольная точка 2

- [ ] Замеры имеют две понятные ветки.
- [ ] Промежуточные сообщения замеров очищаются.
- [ ] План на завтра создать невозможно.

## Задача 6. Сделать восстановление внутренней функцией

**Описание:** Рассчитывать восстановление автоматически перед тренировкой без отдельной кнопки.

**Критерии приёмки:**
- [ ] Решение использует сон, энергию, боль, болезнь, тяжёлые недели и последние чекины.
- [ ] При нехватке обязательного факта бот задаёт только связанный вопрос внутри `/today`.
- [ ] Безопасностный блок рассчитывается кодом и не может быть ослаблен Gemini.

**Проверка:**
- [ ] Табличные тесты нормальной нагрузки, снижения, разгрузки и остановки.
- [ ] Интеграционный тест пути `/today`.

**Зависимости:** Задача 5.

**Предполагаемые файлы:** домен восстановления, слой БД, `src/index.ts`, тесты.

**Размер:** Средний.

## Задача 7. Усилить внутреннюю прогрессию

**Описание:** Сопоставлять выданный план и подтверждённый отчёт, чтобы нагрузка повышалась только после доказанного выполнения.

**Критерии приёмки:**
- [ ] Сравниваются упражнения, подходы, повторения, вес и тип его учёта.
- [ ] RIR 0, неполный объём, нестабильная техника, боль, болезнь или разгрузка блокируют повышение.
- [ ] Следующий план получает решение `повысить`, `повторения`, `удержать`, `снизить` или `заменить`, а Gemini не может его обойти.

**Проверка:**
- [ ] Табличные тесты всех пяти решений.
- [ ] Интеграционный тест `план -> отчёт -> следующий план`.

**Зависимости:** Задачи 5-6.

**Предполагаемые файлы:** `src/exercise-progression.ts`, слой БД, `src/index.ts`, тесты.

**Размер:** Средний.

## Контрольная точка 3

- [ ] Восстановление работает без отдельного экрана.
- [ ] Невыполненный вес не повышается.
- [ ] Все решения воспроизводимы без случайности Gemini.

## Задача 8. Автоматизировать напоминание первой субботы

**Описание:** Заменить ручную настройку одним автоматическим месячным правилом с октября.

**Критерии приёмки:**
- [ ] Напоминание запускается только в первую субботу нужного месяца по Самаре.
- [ ] Полный комплект замеров подавляет повторную отправку.
- [ ] Повтор cron не создаёт дубль.

**Проверка:**
- [ ] Календарные тесты октября, границы месяца и часового пояса.
- [ ] Интеграционный тест дедупликации.
- [ ] Проверка production cron без немедленной отправки.

**Зависимости:** Задача 3 и ответы о составе и времени напоминания.

**Предполагаемые файлы:** `src/reminders.ts`, `src/reminders-db.ts`, миграция настроек, тесты.

**Размер:** Средний.
