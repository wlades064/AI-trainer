# Задачи упрощения Telegram-интерфейса

## Задача 1. Сократить главное меню

**Описание:** Убрать семь лишних кнопок, переименовать возврат упражнения и добавить заметную отмену.

**Критерии приёмки:**
- [x] В меню нет кнопок `Завтра`, `Восстановление`, `Расписание`, `Напоминания`, `Прогрессия`, `Данные`, `Помощь`.
- [x] `🔄 Возврат` заменён на `🧪 Возврат упражнения`.
- [x] `❌ Отмена` вызывает `/cancel` из любой строки меню.

**Проверка:**
- [x] Тесты меню проходят.
- [ ] Ручная проверка `/menu` в Telegram.

**Зависимости:** Нет.

**Предполагаемые файлы:** `src/menu.ts`, `tests/menu.test.ts`, `src/index.ts`.

**Размер:** Средний.

## Задача 2. Очищать временные сценарии ввода данных

**Описание:** Добавить реестр сообщений активных диалогов и безопасную пакетную очистку через Telegram Bot API после успешного завершения или отмены.

**Критерии приёмки:**
- [x] Временные входящие и исходящие сообщения имеют ID и тип сценария.
- [x] `❌ Отмена` закрывает активный сценарий и удаляет связанные сообщения моложе 48 часов.
- [x] Завершённые замеры, чекины и остальные сценарии ввода очищаются только после успешной записи в БД.
- [x] Предтренировочный чекин не удаляет выданную тренировку или предупреждение о здоровье.
- [x] Послетренировочный чекин не удаляет подтверждённую тренировку.
- [x] Тренировки, силовые, итоги, экспорт и лимит ИИ не регистрируются как временные.
- [x] Ошибка удаления не отменяет сохранение или отмену данных.

**Проверка:**
- [x] Тест Telegram API проверяет `deleteMessages` без раскрытия токена.
- [x] Интеграционный тест отмены замеров проходит.
- [x] Тест порядка `сохранение -> очистка` для завершения замеров проходит.
- [x] Тест завершения предтренировочного чекина сохраняет итоговую тренировку.
- [ ] Ручная проверка ошибочного нажатия `Замеры -> Отмена`.

**Зависимости:** Задача 1.

**Предполагаемые файлы:** новая миграция, `src/telegram.ts`, новый модуль временных сообщений, `src/index.ts`, тесты.

**Размер:** Средний.

**Критерии приёмки:**

- [x] История показывает последние даты, семь значений и изменения к предыдущей дате.
- [x] Просмотр истории не вызывает Gemini и не изменяет БД.

**Проверка:**
- [x] Тест форматирования истории.
- [x] Интеграционный тест чтения нескольких дат.
- [ ] Ручная проверка обеих веток Telegram.

**Зависимости:** Задача 2.

**Предполагаемые файлы:** `src/body-tracking.ts`, `src/body-tracking-db.ts`, `src/index.ts`, тесты.

**Размер:** Средний.

**Критерии приёмки:**
- [x] Семь значений сначала надёжно сохранены, затем запускается очистка.
- [x] Весь служебный диалог замеров удаляется по уточнённому правилу владельца.
- [x] Сбой Telegram-очистки не удаляет замеры из БД.

**Проверка:**
- [x] Интеграционный тест порядка `save -> cleanup`.
- [ ] Ручная проверка полного ввода в Telegram.

**Зависимости:** Задачи 2-3.

**Предполагаемые файлы:** модуль временных сообщений, `src/body-tracking-db.ts`, `src/index.ts`, тесты.

**Размер:** Средний.

## Задача 5. Запретить тренировку на завтра

**Описание:** Удалить будущую генерацию и сделать текущий чекин обязательным условием любого нового плана.

**Критерии приёмки:**
- [x] `/tomorrow` не вызывает Gemini и объясняет, что план создаётся только в день тренировки.
- [x] `/today` требует актуальный чекин до нового или ранее сохранённого плана.
- [x] Нельзя обойти болезнь, красные флаги или недостаток данных старым планом.

**Проверка:**
- [x] Тест отсутствия вызова Gemini для `/tomorrow`.
- [x] Тест обязательного чекина для кэшированного плана.
- [ ] Ручная проверка в Telegram.

**Зависимости:** Задача 1.

**Предполагаемые файлы:** `src/index.ts`, расписание, тесты генерации.

**Размер:** Средний.

## Задача 6. Сделать восстановление внутренней функцией

**Описание:** Рассчитывать восстановление автоматически перед тренировкой без отдельной кнопки.

**Критерии приёмки:**
- [x] Решение использует сон, энергию, боль, болезнь, тяжёлые недели и последние чекины.
- [x] При нехватке обязательного факта бот задаёт только связанный вопрос внутри `/today`.
- [x] Безопасностный блок рассчитывается кодом и не может быть ослаблен Gemini.

**Проверка:**
- [x] Табличные тесты нормальной нагрузки, снижения, разгрузки и остановки.
- [x] Интеграционный тест пути `/today`.

**Зависимости:** Задача 5.

**Предполагаемые файлы:** домен восстановления, слой БД, `src/index.ts`, тесты.

**Размер:** Средний.

## Задача 7. Усилить внутреннюю прогрессию

**Описание:** Сопоставлять выданный план и подтверждённый отчёт, чтобы нагрузка повышалась только после доказанного выполнения.

**Критерии приёмки:**
- [x] Сравниваются упражнения, подходы, повторения, вес и тип его учёта.
- [x] RIR 0, неполный объём, нестабильная техника, боль, болезнь или разгрузка блокируют повышение.
- [x] Следующий план получает решение `повысить`, `повторения`, `удержать`, `снизить` или `заменить`, а Gemini не может его обойти.

**Проверка:**
- [x] Табличные тесты всех пяти решений.
- [x] Интеграционный тест `план -> отчёт -> следующий план`.

**Зависимости:** Задачи 5-6.

**Предполагаемые файлы:** `src/exercise-progression.ts`, слой БД, `src/index.ts`, тесты.

**Размер:** Средний.

## Задача 7.1. Перейти к AI-first тренерской логике

**Описание:** Использовать Gemini для неоднозначного разбора и тренерских решений, оставив коду БД, подтверждение, валидацию и жёсткие ограничения безопасности.

**Критерии приёмки:**
- [x] Неудача локального парсера текстового отчёта автоматически вызывает Gemini.
- [x] Ошибка структуры первого ответа Gemini запускает один repair-запрос до сообщения владельцу.
- [x] Gemini выбирает действие прогрессии внутри рассчитанного кодом безопасного потолка.
- [ ] Восстановление разделено на жёсткий кодовый предел и гибкое решение Gemini.
- [x] Определены AI-first сценарии недельного анализа, питания и динамики тела.

**Проверка:**
- [x] Тест `локальный парсер -> Gemini -> repair -> подтверждаемый черновик`.
- [x] Интеграционный тест `план -> отчёт -> Gemini-прогрессия -> безопасный следующий план`.

**Спецификация:** `docs/SPEC_AI_FIRST_COACHING.md`.

**Размер:** Поэтапно, четыре независимых инкремента.
